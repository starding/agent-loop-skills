# 工作循环：总入口

一项重复出现的工作就是一个循环。把工作交给 Agent，按顺序回答三个问题：

1. **建模与分析**：我的时间花在哪里，哪些循环值得交出去。用 `loop-audit`。
2. **工作流**：交出去的循环怎样运行，怎样一轮比一轮轻。用 `loop-spec` 写成说明，按说明运行，每轮结束用 `loop-retro` 沉淀；写作标准用 `my-standards` 生成。
3. **协作礼仪**：Agent 代本人与人沟通时，怎样守住对方的信任。`agent-etiquette` 在起草和阅读消息时生效。

## 工作区

三部分共用当前目录下的 `work-loops/`，文件是唯一的依据：

```
work-loops/
├── NOTES.md            本人的工作环境：用哪些系统、处理哪些渠道、各自怎么称呼
├── LOOPS.md            候选循环与状态：候选、已写说明、运行中、已放弃
└── workflows/
    └── <名称>.md       一个循环一份工作流说明
```

## 判断下一步

只读工作区，不改任何文件。按顺序检查，命中第一条就停：

| 工作区的状态 | 下一步 |
|---|---|
| 没有 `work-loops/`，或 `LOOPS.md` 为空 | 用 `loop-audit` 盘点最近 4 周的工作 |
| `LOOPS.md` 有候选，但都还没写说明 | 用 `loop-spec` 为每周节省最多、风险最低的一项写说明 |
| 有已写说明、尚未运行的循环 | 按说明创建定时任务或事件触发，本人确认任务描述后再创建 |
| 有运行中的循环，最近一轮结束后没有复盘 | 用 `loop-retro` 把这一轮的修改意见写回说明 |
| 以上都没有 | 回到 `LOOPS.md` 挑下一项；距上次盘点超过一个季度时，重新盘点 |

本人说明了想做的事时，直接对应到相应的技能，不必按上表走。

## 输出

1. 当前状态，三四行：已盘点的时间、候选与运行中的循环数量、最近一次复盘的日期。
2. 下一步：用哪个技能、做什么、预计花多少时间。
3. 问本人是否现在开始。
