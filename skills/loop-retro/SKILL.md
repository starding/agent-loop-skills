# 循环复盘与沉淀

每转一轮，把可复用的部分沉淀下来，下一轮就更轻。没有沉淀，每一轮都要从头讲一遍。

## 1. 收集本轮的修改意见

从本轮对话中找出：

- 本人纠正 Agent 的话（「不要……」「太……了」「应该……」）
- 本人重复说明的要求
- Agent 需要追问才拿到的信息
- 本人手动补上的步骤

每条记下原话和发生的场景。

## 2. 归类

| 上下文 | 判断方法 | 沉淀到哪里 |
|---|---|---|
| 标准 | 关于「什么算好」：语气、格式、设计、质量要求 | 规范类技能或规范文档 |
| 做法 | 关于「按什么步骤做」：先查什么、再做什么 | 流程类技能 |
| 触发 | 关于「什么时候开始」：到点、收到某类消息时 | 定时任务或事件订阅 |
| 记忆 | 关于事实与进度：某人是谁、某事到了哪一步、某个系统在哪 | 记忆或事情档案 |

只在本轮有用、不会再出现的内容，不沉淀。

## 3. 提议，确认后再写

用一张表给本人确认：

| 原话 | 归类 | 沉淀到 | 要写入的一句话 |
|---|---|---|---|

规则：

- 先查有没有已经覆盖这一条的地方；有就更新那一处，不重复新建。
- 一条规则只写在一个地方。
- 写入的句子包含原因（为什么这样做），方便以后判断例外情况。
- 修改多人共用的文件或技能前，先说明会影响谁。
- 本人确认后再写入；写完列出改动的文件。

## 4. 下一轮验证

下一轮开始时，检查上一轮沉淀的规则是否生效；没有生效的，说明原因并修正写法。
