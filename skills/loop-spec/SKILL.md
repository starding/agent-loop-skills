# 工作流说明

一项重复出现的工作就是一个循环。工作流说明是这个循环的书面定义：Agent 按它运行，每运行一次就是循环转了一轮。

本技能借鉴了 Matt Pocock 的 [loop-me](https://github.com/mattpocock/skills/tree/main/skills/in-progress/loop-me)（MIT）中的提问方法、工作区组织方式，以及 Trigger、Checkpoint、Push right、Brief 等概念。

## 工作区

读写 `agent-loop/`（见仓库 README）：

- `NOTES.md`：本人的工作环境。为空或很少时，先了解用了哪些系统、处理哪些渠道、各自怎么称呼，再开始写说明。
- `LOOPS.md`：候选循环。没有指定要写哪个时，从这里挑每周节省最多、风险最低的一项，并说明理由。
- `workflows/<名称>.md`：工作流说明，是唯一的依据。提问中有了结论就随时新建、修改或删除说明，不等到最后一次写完；写完更新 `LOOPS.md` 中的状态。

## 提问方式

- 一次问一轮（3–5 个问题），每个问题附上推荐答案，本人可以只回答「同意」。
- 本人的说法模糊时，换成统一的说法，并记录在 `NOTES.md`。
- 看到本人没有注意到的循环（例如这个循环里套着一个更小的、也值得交出去的循环），提出来，记进 `LOOPS.md`。

## 可以用到的概念

以下概念是共用的说法，不是必填清单。一个工作流可以不用 AI、不设确认点、不定时，只要提问结果表明不需要。

| 概念 | 回答的问题 |
|---|---|
| 连接 | 从哪些系统读取、写入哪些系统；需要哪些授权 |
| 标准 | 什么算好；引用哪个规范类技能或文档 |
| 做法 | 按什么步骤做；每一步的输入与输出 |
| 触发 | 什么时候开始：事件（新邮件、新消息）还是定时（每个交易日 8:30）；能用事件就不用定时 |
| 记忆 | 每轮结束记下什么，下一轮从哪里接着做 |
| 确认 | 哪一步需要人确认；确认时给人看什么 |

设确认点时的两条原则：

1. **确认尽量后移**：先把能做的都做完，最后一次性请人确认。
2. **给摘要，不给原稿**：确认时呈现一份能直接做决定的摘要：产出了什么、为什么、原文链接。

对外发送、涉及客户数据、交易或合规判断的步骤，必须设确认点。

## 完成标准

一份说明写完的标准：交给另一个 Agent 实现时，它不需要再问任何问题。还有问题没回答，就继续提问。

## 说明的写法

开头一句话写这个循环解决什么问题、谁受益；其余按这个循环实际需要的概念分节，用不到的不写。涉及客户数据或对外发送时，单列一节「边界」。最后写「验收」：怎样算运行成功。

写完后问本人：是否现在就按这份说明创建定时任务或技能。本人同意后再动手。
