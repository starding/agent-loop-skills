# 工作循环盘点

目标：用本人的工作记录，而不是印象，回答三个问题：

1. 我的时间花在工作循环的哪个环节？
2. 哪些环节要靠我记得去推动？
3. 先把哪 10 件事交给 Agent？

## 背景：工作是一个循环

一项工作一轮一轮推进：**目标**（定方向与优先级）→ **计划**（选方法、拆任务）→ **执行**（做事与协作）→ **反馈**（收集结果、跟进、复盘），反馈再进入下一轮。PDCA、OODA、OKR、Scrum 都是这个结构。

大的循环里套着小的循环：一年的目标、每周的例会、每天早上的消息处理、一份周报。盘点时按循环看，而不是按单件任务看：一件事反复出现，就是一个循环；本人没有注意到的循环，主动提出来。

## 工作区

结果写进当前目录下的 `work-loops/`（见仓库 README）：

- `NOTES.md`：本人用哪些系统、处理哪些渠道、各自怎么称呼。已有内容时先读，再补充。
- `LOOPS.md`：候选循环，即第 5 步排出的前 10 项，每项带状态（候选、已写说明、运行中、已放弃）。已有内容时合并，不覆盖已写说明或运行中的循环。

## 第 1 步：拆分任务（只读）

1. 列出已连接的系统，用一张小表说明：已连接哪些、缺哪些、缺的会影响哪类判断。一个都没有时，不编造，直接进入第 6 节的五个问题。
2. 时间窗默认最近 4 周；数据量大时缩到 2 周，并写明。
3. 以任务为单位，不以岗位职责为单位。每个系统只取能说明「重复」和「耗时」的信息：

| 来源 | 看什么 |
|---|---|
| 日历 | 会议时长与场次、重复例会、会前会后要准备的材料 |
| 消息 | 本人发出的数量与时段、反复回答的问题、反复催办的事 |
| 邮件 | 结构相近的邮件、需要从多处汇总才能写的邮件 |
| 文档 | 定期新建的同类文档、从模板复制的文档 |
| 任务 | 反复创建的同类任务、长期拖延的任务 |
| Agent 会话记录 | 每个会话的第一条请求：本人反复让 Agent 做什么、哪些仍是手动发起 |

规则：

- 对工作系统只读：盘点过程中不发消息、不改文档、不建任务；只在本地工作区写结果。
- 统计为主，例子只引一两句，能给链接就给链接。
- 客户姓名、账户、持仓、联系方式只记类别（例如「某类客户沟通」），不出现在结果里。
- 拿不到的数据直接说明，不推测补齐。
- 消息搜索有条数上限时，按天查询再合并。

## 第 2 步：归入环节

按任务在循环中的作用归入环节：

| 任务在做什么 | 环节 |
|---|---|
| 定方向、定优先级、取舍、对外承诺 | 目标 |
| 选方法、调研、比较方案、做原型 | 计划 |
| 推进、沟通、审批、分派 | 执行 |
| 收集结果、跟进进度、催办、汇总 | 反馈 |

环节决定了工作的典型性质，性质决定了能交给 Agent 的程度：

| | 有既定做法 | 没有既定做法 |
|---|---|---|
| 结果需要人把关（对外或不可逆） | **执行**：例行沟通与审批 | **目标**：判断与关系 |
| 结果不需要人把关（自用或可迭代） | **反馈**：收集、跟进与汇总 | **计划**：调研与原型 |

越靠左下越适合交给 Agent，越靠右上越需要人负责。个别任务与所在环节的典型性质不同时（例如需要对外发出的汇总），按它的实际性质处理，并在结果中注明。

## 第 3 步：测量时间

给出四个环节的次数、占比和 2–3 个具体例子。时间按日历时长、消息往返次数或文档篇幅估算，标「估」。

## 第 4 步：匹配处理方式

先找出「依赖人记得推动」的环节，再按环节匹配：

| 环节 | Agent 的处理方式 | 人的角色 |
|---|---|---|
| 反馈 | 定时或事件触发，自动执行 | 查看结果 |
| 执行 | 按规范起草，进入待确认队列 | 确认后发出 |
| 计划 | 产出多个初稿，按评审意见迭代 | 定方向、评审 |
| 目标 | 整理材料、提出反对意见，不自动执行 | 决策并负责 |

方法从轻到重选：定时任务 → 模板起草 → 事件触发 → 知识库问答 → 多步工作流。工具优先用用户已有的。

## 第 5 步：排序

每周可节省时间（估）= 每周次数 × 单次耗时 × 可交给 Agent 的比例（高 0.8 / 中 0.5 / 低 0.2）。涉及对客发送、交易、合规判断的事项风险高，只建议「Agent 起草、人确认」，同等条件下往后排。取前 10。

## 第 6 节：数据不够时的五个问题

一次问完，回答与已有数据合并后再排序：

1. 每天上班第一个小时通常在做什么？
2. 每周固定要交或要发的东西有哪些？
3. 最近一周，哪件事做了三次以上？
4. 最常被同事或客户问的三个问题是什么？
5. 哪件事最烦，但又不得不做？

## 输出

对话里给出以下内容，同时把第 2 项写进 `LOOPS.md`，把盘点中了解到的系统与说法写进 `NOTES.md`：


1. **概览**（三四行）：时间窗、数据源与缺口、四个环节的时间占比、前 10 项合计每周可节省的小时数（估）、最建议先做的一件事。
2. **提效点总表**：

| # | 事项 | 环节 | 依据 | 每周次数 | 单次耗时 | 每周节省（估） | 方法 | 工具 | 风险 |
|---|---|---|---|---|---|---|---|---|---|

3. **前 3 项的落地步骤**：现在怎么做、改成什么样（Agent 做哪一步、人做哪一步）、今天 15 分钟内能完成的第一步（定时任务直接给出可复制的任务描述，格式见 loop-spec 技能里的 `scheduled-task.md`）、注意事项（权限、合规、需要谁同意）。
4. **已经交给 Agent 的事**：其中哪些仍需手动触发。
5. **没有列入的事**：看起来耗时但不建议交给 Agent 的事，以及原因。

## 写法

- 用通行的职场说法；首次出现的术语用一句话解释。
- 所有时间数字标「估」，宁可少估。
- 最后问用户：是否现在用 `loop-spec` 把第 1 项写成工作流说明；简单的定时任务可以直接按模板创建。用户同意后再动手，建之前把任务描述给用户确认。
